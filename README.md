# Kamioka Logical Explainer

**平易な言葉で、筋道を鋭く。**

身近な出来事から始め、世間の建前を問い直し、自分の物差しで論理を組み立て、本質をわかりやすく伝えるための日本語 Agent Skill です。

上岡龍太郎氏の説明術に見られる構造を参考にしていますが、ご本人の発言・芸風の模倣を目的としたものではありません。

## できること

- 難しい話を、専門用語を使わず分かりやすく説明する
- 「当たり前」とされる意見の前提を見直す
- 身近な具体例から、問題の仕組みや背景を読み解く
- 説教ではなく、逆説や気づきで締めくくる文章を作る
- 長くて分かりにくい解説を、短く論理的に書き直す

## 説明の組み立て方

1. **枕**：誰もが思い浮かべられる身近な出来事から始める
2. **建前と物差し**：通説を問い直し、判断基準を明確にする
3. **具体的な裏付け**：効き目のある事実や数字を少数だけ使う
4. **本質への接続**：具体例から、背景の仕組みを導き出す
5. **着地**：説教せず、逆説や余韻を残して終える

詳しい指示は [SKILL.md](./SKILL.md) を参照してください。

## インストール

[skills CLI](https://github.com/vercel-labs/skills) に対応したエージェントへインストールできます。

```bash
npx skills add tamutamu/kamioka-logical-explainer
```

スキルを一覧で確認する場合：

```bash
npx skills add tamutamu/kamioka-logical-explainer --list
```

CLI を使わず、`SKILL.md` を対応エージェントのスキルディレクトリに配置することもできます。

## 使い方

たとえば、次のように依頼します。

> Kamioka Logical Explainer を使って、「なぜ会議は長くなるのか」を説明してください。

> 「なぜ今も学歴が重要なのか」を、中学生にも分かる例えで説明してください。

> この文章を、具体例から始まり、最後に逆説が残る論理的な説明へ書き直してください。

## 短い出力例

> 30分で終わる話でも、1時間の会議を設定すると、なぜか1時間かかります。
>
> 会議は、話すことがあるから長いのでしょうか。それとも、時間があるから話すことを増やしてしまうのでしょうか。
>
> 会議の価値を話した時間で測れば、1時間は立派な実績です。しかし、決まったことや進んだ仕事で測れば、10分の会議に負けることもあります。
>
> 仕事を進めるために会議を開いたのに、会議をすることが仕事になってしまう。そこに、この問題の面白さがあります。

この例はスキルの出力イメージを示すもので、上岡龍太郎氏の発言の引用ではありません。

## 設計上の注意

- **筋が通っていること**と、**事実として正しいこと**は別です。事実や数字は確認できるものだけ使います。
- 一つの例を、根拠なく「すべての人」に当てはめません。
- 相手を言い負かすことではなく、読み手が自分で理解できることを目標にします。
