# Plainwise

> **開発ブランチです。** このブランチのSKILL.mdは「問いを小さくして盲点を見抜く」方向に再設計した候補です。以下の出力例と従来の検証結果は旧版によるものです。新候補の効果は未検証で、[新しい比較手順](./evaluation/README.md)を用意しています。

**聞いた人が、思わず「なるほど、そういうことか」と言いたくなる説明を。**

Plainwiseは、ただ結論を並べるのではなく、**身近な場面で予想させ、思わぬ食い違いを見せ、その原因を論理で解く**日本語のAgent Skillです。

上岡龍太郎氏の説明の構成から着想を得ていますが、関西弁や本人の口調・発言を模倣するものではありません。自然な**標準語の語りかけ**を目指します。

## どう違うのか

「システムのエラー率が1％なのに、なぜ苦情が多いのか？」なら、次のような説明を生成します。

> 1回の通信失敗は1％でも、20回すべて成功しないと操作が完了しないとします。では、利用者が見る失敗率も1％でしょうか。
>
> 20回すべて成功する確率は、`0.99²⁰ ≒ 81.8％`。
>
> したがって、少なくとも1回失敗する確率は、`1 − 0.99²⁰ ≒ 18.2％`です。
>
> つまり利用者は、約5.5回に1回の割合で失敗に遭います。苦情が多いのは、通信単体の1％ではなく、「失敗する機会が20回ある一連の操作」を体験しているからです。

※独立した20回の通信で、どれか一つでも失敗したら操作全体が失敗する**仮定**の例です。実際に生成した出力の一部を抜粋しています。

ポイントは、**「通信1回のエラー率」から「利用者が完了できない割合」へ、物差しを切り替えること**です。計算や例えでこの違いを実際に確かめられる説明を目指します。

## 使い方

```bash
npx skills add tamutamu/plainwise
```

例えば「Plainwiseを使って、なぜ会議で全員が賛成しても仕事が進まないのか説明してください」と質問します。

## 検証と限界

同じモデルでの通常回答、強い一般指示、各版のPlainwiseを比較し、複数の題材で評価・修正を繰り返しました。[実際の回答と匿名評価](./EVALUATION.md)を公開しています。

**文章の構成と出力の正確さは検査済みですが、実際の人間がどれほど「なるほど！」と感じるか、理解が定着するかは未実証です。** すべての質問でPlainwiseが通常AIを上回るという主張はしません。
